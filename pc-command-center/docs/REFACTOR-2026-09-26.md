# Refactor and quality pass — 26 September 2026

This pass re-checked the improved 2.2.4 tree and focused on changes that are safe to validate without a live Ubuntu/GTK/hardware test machine.

## Architecture

- Added `core.configuration` as the single typed configuration-inventory boundary. Desktop, privacy, and system-tweak providers are isolated so one failed probe no longer blanks the inventory.
- Reworked `core.config_audit` into a versioned audit model with stable event IDs, explicit mutation metadata support, config keys, redaction, bounded retention, and backwards-compatible reads.
- Extended `Step` with `mutates`, `config_key`, and future-ready `timeout` metadata instead of forcing UI/executors to infer every property from commands.
- Fixed audit classification: merely running a command as root no longer automatically claims that PC Command Center changed configuration.
- Bounded newline-free command output buffering in both async/core and GTK runners to prevent an extremely long output line from growing memory without bound.

## Configuration UI

- Rebuilt Configuration around the typed inventory service rather than probing subsystems directly in the page.
- Added live summary cards for managed settings, groups, recorded changes, and unknown values.
- Added independent search for current settings and change history.
- Added per-setting source and explanation, recommendation state, admin/user badges, partial-provider warning state, and explicit healthy collection state.
- Preserved responsive layout, accessible labels, redacted history, and compact-screen behavior.

## Verification

- `pytest -q`: 228 passed, 2 skipped.
- `python -m compileall -q src tests`: passed.
- The two skipped tests remain environment-dependent GTK tests.
- `ruff` is declared by the project but is not installed in this review environment, so a fresh Ruff run was not claimed.

## Still requires a real Ubuntu release environment

Polkit interaction, GTK visual regression at multiple scales, package/boot/storage mutations, hardware probes, install/upgrade/rollback/uninstall, and the larger privileged-helper redesign must be validated in provisioned VMs or representative hardware before release certification.
